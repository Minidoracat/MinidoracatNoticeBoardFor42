# 服主指南 — Minidoracat Notice Board for B42

公告內容放在 Zomboid 的 `Lua/NoticeBoard/` 目錄，不放在 MOD 內。修改公告文字不需要重新發布 Workshop；MOD 會依 Sandbox 設定的輪詢間隔重新讀取檔案並推送給玩家。

## 公告目錄

| 遊戲模式 | 公告根目錄 | 說明 |
|---|---|---|
| Dedicated server | 伺服器主機的 `Zomboid/Lua/NoticeBoard/` | 這裡的 `Zomboid` 是 dedicated server 使用的 cachedir；若啟動參數指定其他 `-cachedir`，請改用該目錄。 |
| Co-op host | `%USERPROFILE%/Zomboid/Lua/NoticeBoard/` | Co-op 伺服器是獨立的 `GameServer` 子程序，但 `CoopMaster.launchServer()` 會把主機目前的 cachedir 以 `-cachedir=` 傳給子程序，因此公告仍放在開房玩家本機的同一個 Zomboid 目錄（`CoopMaster.java:72-119`）。 |
| 單人遊戲（SP） | `%USERPROFILE%/Zomboid/Lua/NoticeBoard/` | 單人遊戲直接由本機讀取，不經多人網路同步。 |

在公告根目錄下，以 PZ Translate 語系代碼建立子目錄。公告可直接放在語系根層，也可放進
`categories.txt` 已宣告的分類目錄；玩家可用文件樹工具列的「全部展開」與「全部收合」按鈕一鍵操作所有分類，不必逐個點擊。「全部展開」在玩家曾明確收合側欄時會一併打開側欄（若玩家未手動調整，預設側欄就是展開的）；「全部收合」只關閉分類，側欄本身不會收合、側欄偏好也保持不變。窄視窗的強制收合仍優先生效。

```text
Zomboid/Lua/NoticeBoard/
├── README.txt          管理員說明，由「重建範例」寫入；不是公告
├── categories.txt
├── CH/
│   ├── 10_welcome.md
│   ├── 10_news/
│   │   └── 20_update.md
│   └── 20_rules/
│       └── 30_server_rules.txt
├── EN/
│   ├── 10_welcome.md
│   ├── 10_news/
│   │   └── 20_update.md
│   └── 20_rules/
│       └── 30_server_rules.txt
└── JP/
    └── 10_welcome.md
```

### 公告分類（可選）

伺服器啟動時會在公告根目錄建立一份純註解的 `categories.txt` 範本；已存在時絕不覆蓋。
**唯一會覆蓋它的是管理員按下「重建範例」**（見「一鍵重建範例」一節）：那顆按鈕會用只宣告 `10_news` 與 `20_rules` 的版本直接取代這個檔。
每個有效行宣告一個分類的語系標籤：

```text
10_news|EN|News
10_news|CH|最新消息
20_rules|EN|Server Rules
20_rules|CH|伺服器規則
```

格式固定為 `<分類 key>|<PZ 語系代碼>|<顯示名稱>`：

- 分類 key 同時是實體目錄名，只能用 ASCII 英數、底線與連字號，長度最多 48 字元；第一段數字前綴決定側欄順序。
- 同一 key 可依語系寫多行。玩家看到的標籤依「玩家語系 → `DefaultLanguage` → 該 key 第一個合法標籤 → key 原文」回退。
- 最多宣告 32 個分類；顯示名稱最多 80 字元，不得含控制字元或 `|`。
- `categories.txt` **只宣告目錄，不會建立目錄**。請自行建立 `NoticeBoard/<LANG>/<分類 key>/` 並放入 `.md`／`.txt`。
- PZ 的目錄列舉 API 明確排除目錄（`LuaManager.java:6024-6068`），所以 MOD 無法自動發現未宣告的分類。資料夾沒有列進 `categories.txt` 時，其中公告不會出現，log 也無法直接指出那個未知目錄。
- 公告的穩定 ID 仍是**裸檔名**，分類路徑不算 ID。因此把同一檔案搬到另一個已宣告分類，不會重置已讀狀態或重新通知；但同一語系內所有分類與語系根層的檔名必須全域唯一。
- 同一 ID 在玩家語系與 `DefaultLanguage` 放進不同分類時，內容仍由玩家語系覆蓋，分類位置則以 `DefaultLanguage` 為準，server log 會記 `category-conflict`。
- `categories.txt` 暫時讀不到或含格式錯誤時，server log 會記 `category-*`；已知的上一輪分類目錄仍會繼續掃描，公告暫時退到「一般公告」，避免公告消失並清掉玩家已讀狀態。只有一份**可完整解析且確實移除 key** 的設定才會停止掃描該分類。
- 語系根層的既有檔案歸在側欄的「一般公告」。不使用分類時完全不必修改現有目錄。

### 玩家會看到哪些公告（**這裡容易誤解，先讀完再放檔**）

規則只有一條（`NBReader.composeLanguage`）：

> **`DefaultLanguage` 目錄裡「未標記 `.only`」的檔案是全體共用的底稿，玩家語系目錄的同名檔案覆蓋上去。**

換句話說，玩家看到的是「`DefaultLanguage` 的全部檔案**扣掉標記 `.only` 的那些**」聯集
「自己語系的全部檔案（含 `.only`）」，同一個檔名出現在兩邊時用玩家語系那份。
`DefaultLanguage` **不是**「找不到才去翻的備援」——它裡面每一份**沒有標記**的檔案都會出現在
**每一個**語系玩家的面板上；標記 `.only` 的則只給它所在的那個語系（見下方「只給某個語系看」）。

分類只改變側欄分組，不改變可見範圍；fallback 與 `.only` 仍以裸檔名和語系目錄判定。

以 `DefaultLanguage = EN` 為例：

| 檔名 | 放在 EN | 放在 CH | CH 玩家 | EN 玩家 |
|---|---|---|---|---|
| `10_welcome.txt` | ✅ | ✅ | 看到 CH 版（覆蓋底稿） | 看到 EN 版 |
| `30_rules.txt` | ✅ | ✗ | **看到 EN 版**（底稿，沒有中文版可覆蓋） | 看到 EN 版 |
| `40_ch_only.txt` | ✗ | ✅ | 看到 CH 版 | **看不到** |

所以：

- **想讓所有人都看到（不管語系）**：放進 `DefaultLanguage` 目錄。翻譯過的語系再放同名檔覆蓋即可，
  沒翻譯到的語系會看到原文——這正是 fallback 的用意，服主只寫一份也不會有人漏看公告。
- **想只給某個語系看**：兩種做法，**當下效果相同、但穩定度不同**。
  - 檔名加 `.only` 標記：`EN/20_en_notice.only.txt`、`CH/40_ch_notice.only.md`。
    **標記過的檔案永遠不會被鋪成其他語系的底稿**，就算它放在 `DefaultLanguage` 目錄裡也一樣。
    這是唯一能在 `DefaultLanguage` 目錄裡表達「只給這個語系」的方法——沒有標記時，
    那個目錄的每一份都是全體共用的底稿。
  - 或者放進**非** `DefaultLanguage` 的語系目錄，且該檔名在 `DefaultLanguage` 目錄裡不存在
    （compose 只從 `DefaultLanguage` 鋪底稿，不會反向從別的語系補進來）。**這只是「暫時限定」**
    ——語意綁在「哪個語系是 `DefaultLanguage`」上，哪天你把 `DefaultLanguage` 改成這個語系，
    同一批檔案會**全部變成共用**、對所有語系的玩家公開。要穩定的限定語意一律加 `.only` 標記。

> **改檔名會讓該公告對「看得到新檔名的玩家」重新變成新公告**（跳通知、響提示音、側欄紅點）。
> 已讀狀態是以**檔名**當鍵記在玩家本機（`readstate.ini` 的 `<伺服器>|<檔名>=<內容雜湊>`），
> 新檔名沒有已讀記錄，舊檔名則因為不在 manifest 內而被清掉。沒有「靜默改名」的機制。
>
> 加上 `.only` 標記時要分兩群人看，因為改名同時改變了可見範圍：
>
> - **該語系的玩家**（例如 `EN/30_rules.txt` → `EN/30_rules.only.txt` 的 EN 玩家）：
>   看到的是一份新 ID，會收到一次通知。
> - **其他語系的玩家**：那份公告直接從他們的清單消失（`.only` 不鋪底稿），側欄項目不見、
>   **不會**收到通知。
>
> 若是不改變可見範圍的單純改名（例如只調整數字前綴排序），那就是「所有看得到它的玩家」
> 都收到一次通知。想避免打擾就挑離峰時間改，或把改名跟真正需要通知的內容更新併成一次做完。

  標記的形狀是「副檔名前面那一段剛好是 `only`」：`x.only.txt` ✅、`x.only.md` ✅、
  `20_only.txt` ✗（`only` 在名稱裡不算）、`x.onlyy.txt` ✗。
- 檔案內容裡的標題文字（例如寫成 `# [EN] Rules - EN only`）**只是文字**，MOD 不解析它。
  可見範圍只由兩件事決定：**檔案放在哪個語系目錄**，以及**檔名有沒有 `.only` 標記**。
  標題怎麼寫、內文寫什麼都不參與判斷。


玩家也可以在面板工具列右側的「語言」按鈕自行指定公告語系，不必跟著遊戲語系走：選單只會列出**這台伺服器實際有內容的語系目錄**，加上一個「自動（跟隨遊戲語系）」選項。選擇會記在玩家本機的 `Zomboid/Lua/NoticeBoard/settings.ini`（全域偏好，不分伺服器），下次進場自動沿用。切換後會立刻重新註冊並重建文件樹——公告內容是伺服器權威推送的（玩家端只留著目前語系的那一份），所以換語系是一次網路請求而不是純本機切換：伺服器對每位玩家的**語系切換**有 3 秒冷卻（與進場註冊、同步逾時補救的 10 秒冷卻分開計算），冷卻期間切換會顯示「請再等 N 秒」的提示，並在冷卻結束後自動送出。

關於這份選單，有兩件事值得先知道：

- **列出來的是 PZ 的 Translate 語系代碼原文**（`CH`、`JP`、`PTBR`、`ES_CL`、`STREW`……），不是「繁體中文」「日本語」這類在地化名稱。這些代碼直接對應你在公告根目錄下建立的子目錄名稱，玩家回報問題時報的也是同一組字串，比較好對。
- **偏好語系的目錄被你清空之後**（例如你把 `NoticeBoard/JP/` 裡的檔案全刪了），那個語系就不再出現在伺服器推送的清單裡，但玩家本機的偏好還留著。此時選單會**額外補一列**顯示成 `JP（這台伺服器沒有此語系的公告）` 並打勾，讓玩家看得出目前生效的是什麼；點它仍然可以重送切換請求。玩家實際看到的內容則依既有規則退回 `DefaultLanguage`。

## 檔名規則與排序

- 支援 `.md` 與 `.txt`，副檔名不分大小寫；兩者的解析能力相同。
- 使用 `<數字前綴>_<ASCII 名稱>.<副檔名>`，例如 `10_welcome.md`、`20_server_rules.txt`。
- 檔名只使用 ASCII 字母、數字、底線與連字號。中文可放在檔案內的標題與內容，不要放進檔名。
- 檔名長度上限 128 字元（含副檔名），且不得含控制字元或 `|`、`=`。超過或含這些字元的檔案會被整份跳過，並在伺服器 log 記錄 `invalid-id`（此限制用於保證跨伺服器已讀狀態與網路 manifest 的完整性）。
- 同一則公告在不同語系中必須使用完全相同的檔名，包含副檔名。檔名就是公告的穩定 ID，也是跨語系 fallback 的比對依據；同一語系內即使分屬不同分類，也不得重複檔名。
- 分類內的公告先依開頭數字由小到大排序；數字相同時依檔名排序。沒有數字前綴的檔案排在有前綴的檔案之後。
- 側欄公告名稱取自檔案內第一個 `# 標題`。找不到一級標題時，直接顯示完整檔名。
- 公告檔本身不支援 YAML/front-matter、排程或到期日；分類是由根層 `categories.txt` 提供的外部 metadata。

建議每次調整排序時留出間隔，例如使用 `10_`、`20_`、`30_`，日後即可插入 `15_event.md` 而不必替所有檔案重新命名。

### Emoji 與特殊符號

- **檔案與同步層支援**：公告檔與 `categories.txt` 由 Java 以 UTF-8 讀取，hash、分塊、重組與側欄截字都會保留 UTF-16 surrogate pair；emoji 不會把同步協定或已讀狀態弄壞。
- **畫面顯示不保證，實務上視為不支援**：PZ 使用預先烘焙的 BMFont 字形，不會呼叫作業系統 emoji 字型作 fallback。42.20.4 內建字型找不到常見的 `😀`、`☺`、`♥`、`❤`；缺字依字型可能變成 `?` 或直接沒有寬度／不繪製（`AngelCodeFont.java:288-309,525-553`）。
- 因此不要用 emoji 傳達必要資訊，也不建議放進公告標題或分類名稱。固定介面語意請用 Minidoracat UI Library 的共用圖示；公告內容需要圖案時，用 `NoticeBoard/images/` 的 PNG，玩家才一定看得到。

## 支援的 Markdown 語法

本 MOD 依 CommonMark 解析下表所列的語法。**沒列在表上的一律不解析**，會原樣當文字顯示；做不到的項目與原因整理在後面的「與標準 Markdown 的已知差異」。

### 區塊語法

| 功能 | 寫法 | 實際顯示行為 |
|---|---|---|
| 一級標題 | `# 伺服器公告` | 大字、白色、**置中**（引擎的 `<H1>` 寫死置中）。**該行含圖片時整行改為靠左**（字級與顏色不變，見「顯示與排錯」）。第一個 H1 同時作為側欄公告名稱：**側欄上不會出現圖片標記**，`![說明](路徑)` 只留下說明文字、`<IMAGE:路徑>` 整段拿掉，剝完是空的就往下找下一個 `#`（都沒有才用檔名）。 |
| 二級標題 | `## 今日更新` | 中字、淺灰、靠左。 |
| 三級標題 | `### 小節` | 與 H2 同字級，改用青色區分（引擎只有三階字級，見已知差異）。 |
| 四／五／六級標題 | `#### 甲` / `##### 乙` / `###### 丙` | 內文字級，靠亮度階梯逐級變暗（無法再縮小字級）。 |
| 段落 | 空白行分隔 | 段落內的單一換行會**併回同一段**並自動重排（與標準 Markdown 相同）。 |
| 強制換行 | 行尾打兩個空白，或行尾放一個 `\` | 在同一段落內強制斷行。 |
| 無序清單 | `- 第一項` / `* 第一項` / `+ 第一項` | 三種記號一律顯示成 `-` 項目符號（與 HTML 的 `<ul>` 一致）。 |
| 有序清單 | `1. 第一項` / `1) 第一項` | **自動編號**：只看第一項的起始號，之後遞增，所以 `1. 1. 1.` 會顯示 1./2./3.。 |
| 巢狀清單 | 子項縮排 2 個以上空白 | 每層多縮排一段，最多 4 層，超過的壓在第 4 層。 |
| 清單項續行 | 下一行縮排接著寫 | 併回上一個清單項（縮排是必要的，沒縮排會變成新段落）。 |
| 引言 | `> 引用內容` / `>> 巢狀引言` | 縮排＋灰字，行首加一個 ASCII `|` 記號；最多 4 層。 |
| 分隔線 | `---` / `***` / `___` / `- - -` | 三個以上同樣的記號、且該行沒有其他文字時，顯示水平分隔線。 |
| 圍欄程式碼區塊 | ` ```lua ` … ` ``` `（或 `~~~`） | 淡藍字、整塊縮排，**內部不再解析任何 Markdown 語法**，`<`、`>` 一律轉義。 |
| 表格 | — | 不支援，見已知差異。 |
| PZ 原生 RichText 標記 | 見下方白名單 | 白名單內的標記原樣交給 `ISRichTextPanel`，供進階排版使用；白名單外的標記會被當成一般文字顯示。 |

### 行內語法

| 功能 | 寫法 | 實際顯示行為 |
|---|---|---|
| 醒目文字（粗體） | `**重要內容**` / `__重要內容__` | 琥珀色。PZ RichText 沒有粗體字型，只能用顏色表示。 |
| 斜體 | `*強調*` / `_強調_` | 綠色。PZ RichText 沒有斜體字型，只能用顏色表示。 |
| 粗斜體 | `***兩者***` | 顏色堆疊後內層勝出，實際只看得到斜體的綠色。 |
| 行內程式碼 | `` `getTexture()` `` | 粉色。沒有等寬字型也沒有底色框。支援多重反引號（`` ``含有 ` 的內容`` ``）。**內部不再解析任何 Markdown 語法**，連 `` `[文字](網址)` ``、`` `<https://…>` `` 都只會原樣顯示、不會變成連結。 |
| 刪除線 | `~~作廢~~` | **只把 `~~` 記號吃掉、顯示純文字**：引擎沒有刪除線效果。 |
| 連結 | `[官方網站](https://projectzomboid.com)` | 可點擊的藍色文字，與一般 Markdown 相同是行內元素——可以放在句子中間、清單項或粗體裡，滑鼠移上去只有連結文字本身會亮起底線。 |
| 自動連結 | `<https://projectzomboid.com>` | 同上，顯示文字就是網址本身。只接受 `http` / `https`。 |
| 反斜線逸出 | `\*`、`\#`、`\-`、`\<` … | 反斜線後接任一 ASCII 標點時，該標點只當普通文字，不觸發語法。 |
| 圖片（伺服器同步） | `![替代文字](images/rules.png)` | 從伺服器的 `NoticeBoard/images/` 同步到玩家本機後顯示；同步完成前顯示 `[替代文字]`。 |
| 圖片（圖包 MOD） | `![替代文字](media/textures/MyNoticeImages/rules.png)` | 從已載入 MOD 的貼圖路徑顯示圖片；缺圖時顯示 `[替代文字]`。 |
| 圖片尺寸 | `![替代文字](images/rules.png =600x200)`／`=600x`（只給寬）／`=x200`（只給高） | **路徑與 `=` 之間至少要有一個空白。** 只給一邊時另一邊依原圖比例推算。同步圖與圖包 MOD 兩條路徑都適用。指定值仍會被夾在面板可用寬度與內容高度的 3 倍之內（寫 `=5000x` 不會撐爆版面）。不寫尺寸時行為與以往完全相同。**格式打錯時整行會以原始 markdown 顯示、圖片不會出現**，見下方說明。 |

一般文字中的 `<`、`>` 會被轉義成可見文字。

**原生標記白名單**（只有這些會被放行，其餘一律轉義成可見文字）：

- 無參數：`<LINE>`、`<BR>`、`<H1>`、`<H2>`、`<TEXT>`、`<CENTRE>`、`<LEFT>`、`<RIGHT>`、`<SPACE>`、`<POPRGB>`
- 帶參數：`<RGB:r,g,b>`、`<PUSHRGB:r,g,b>`、`<SIZE:字型>`、`<INDENT:n>`、`<IMAGE:路徑>`、`<IMAGECENTRE:路徑>`
- `<SIZE:>` 只放行引擎認得的六個字型名：`small`、`medium`、`large`、`intro`、`credits1`、`credits2`。其餘的值在引擎裡本來就沒有任何效果，而且引擎對每條標記做的是**子字串**比對，`<SIZE:INDENT:zz>` 這種把另一條標記藏在參數裡的寫法會同時命中兩個分支、讓整份公告死掉。
- **參數內不可以有空白**：`<RGB:1, 0, 0>` 會被引擎切成兩半、把版面弄壞，所以不放行，會直接轉義成可見文字。要寫成 `<RGB:1,0,0>`。同理，圖片路徑含空白時 `![說明](我的 圖.png)` 也不會變成圖片，而是原樣顯示。
- **參數個數與型別也要對**：`<RGB:>` / `<PUSHRGB:>` 必須剛好三個數字，`<INDENT:>` 必須是一個數字。少一段或不是數字（`<RGB:1,0>`、`<INDENT:abc>`）會讓引擎拿 `nil` 當顏色或縮排值去算，**整份公告會變成「無法顯示這則公告」**，所以這些寫法一律不放行、直接轉義成可見文字，你一眼就看得到打錯在哪。`<IMAGE:>` / `<IMAGECENTRE:>` 的參數規則見「圖片與圖包 MOD」一節。

引擎另有 `<RED>`、`<GREEN>`、`<ORANGE>`、`<GHC>`、`<BHC>`、`<SETX:n>`、`<KEY:...>`、`<VIDEOCENTRE:...>` 等標記，但**本 MOD 刻意不放行**：引擎解析這些標記時使用子字串比對，放行後可能被構造成崩潰或路徑穿越。要上色請改用 `<RGB:r,g,b>`。

**排版注意**：引擎在每個樣式邊界切開文字後會把兩側的空白吃掉，所以 MOD 會把**你在來源檔裡寫的空白**換成引擎不會吃掉的空白字元保住：`請閱讀 **規則** 。` 顯示成「請閱讀 規則 。」、`(**規則**)` 顯示成「(規則)」——有空白就有空白、沒空白就緊貼，與一般 Markdown 一致。唯一的例外是行內程式碼：它的兩側固定各留一個空白寬（連同反引號一起顯示），讓 `` 尺寸`=600x200` `` 這種中文緊接技術符號的寫法讀得出邊界。

## 與標準 Markdown 的已知差異

以下全部是 `ISRichTextPanel`（PZ 的文字面板）的能力上限或刻意的安全取捨，不是 bug。誠實列在這裡，免得你花時間試。

### 引擎做不到的

| 項目 | 實際行為 | 原因 |
|---|---|---|
| 粗體、斜體 | 只能換顏色 | 引擎的 `<SIZE:>` 只切換 UIFont 列舉（`ISRichTextPanel.lua:122-144`），沒有任何字重或斜體變體，`drawText` 也沒有樣式參數（`:672`）。UIFont 列舉是固定的，MOD 只能替換既有字型檔（連帶改變遊戲其他畫面）或用 Lua 自載字型自繪（要重寫整套排版）；兩條路都得像遊戲本身一樣按語系各帶一套粗體圖集（原版 `media/fonts/` 就分 CH／CN／JP／KO／TH／RU 等目錄），每種字級設定各一份，光中文一套就一萬多字、數十 MB，漏掉的語系在粗體區段會直接缺字。本 MOD 判斷不值得，維持顏色區分。 |
| 粗斜體 | 只看得到斜體色 | 顏色是堆疊（`:68-80`），巢狀後內層勝出。 |
| 刪除線 | 記號被吃掉，文字照常顯示 | 引擎沒有刪除線繪製能力。 |
| H1 置中 | 純文字的 `#` 標題一定置中，無法指定靠左；**含圖片的 `#` 標題則自動改為靠左**（`![說明](路徑)` 與 `<IMAGE:路徑>` 皆適用，`<IMAGECENTRE:>` 除外） | `<H1>` 直接寫死 `orient = "centre"`（`:30`），而置中只用**文字**寬度算位置、完全不計圖片寬度（`:644-648`），圖片又是另外一套座標（`:595` 對 `:665`）——兩者硬湊會讓圖文錯開。因此含圖片的那一行改用 `<LEFT>` + `<SIZE:large>` 排版，字級與顏色與 `<H1>` 完全相同。`<IMAGECENTRE:>` 被引擎強制畫在水平正中（`:205-206`）、與對齊設定無關，改靠左沒有幫助，所以維持置中。想讓純文字大標也靠左，可以自己用同一組白名單標記排版。 |
| H4 / H5 / H6 字級 | 全部是內文字級，只有亮度不同 | `<SIZE:>` 只認 small/medium/large/intro/credits1/credits2，而 `small` 就是內文預設字型 `UIFont.NewSmall`（`:765`）——沒有比內文更小的字級可用。H6 與內文的亮度差很小，**不建議用到 H5 / H6**。 |
| 程式碼區塊的行內對齊 | 只有**行首**縮排會保留 | 引擎會把每個 token 去頭尾空白、再用單一空白重組（`:497-499`、`:513`、`:542`），行內的連續空白一定會塌成一個。也沒有等寬字型可用，所以 ASCII 表格、對齊的註解欄都會跑掉。 |
| 程式碼區塊的長行 | 照樣自動換行 | 引擎在超過內容寬度時強制換行（`:502`），無法關閉，也沒有橫向捲軸。 |
| 行內程式碼 | 只有顏色，沒有底色框 | 引擎沒有行內背景色原語。 |
| 表格 | **不支援** | 引擎沒有任何欄位排版原語，`drawText` 只吃 (x, y, 顏色, 字型)。要做表格得自己逐格量測字寬、逐格定位，還要自己處理儲存格內換行——成本極高而且成品仍然半殘。請改用清單或程式碼區塊排版。 |

### 標準以外的擴充

| 項目 | 實際行為 | 說明 |
|---|---|---|
| 圖片尺寸 `![alt](path =600x200)` | 依指定尺寸顯示 | **不在 CommonMark 核心**，是 Markdown 生態（markdown-it-imsize、Pandoc、GitLab 等）通行的擴充語法，本 MOD 一併支援。純 CommonMark 解析器會把 `=600x200` 當成路徑的一部分，因此帶尺寸的公告檔在其他工具預覽時圖片會顯示不出來。不需要尺寸時不要寫，行為完全等同標準語法。 |

#### 尺寸格式打錯時會怎樣

尺寸尾段只認 `=<寬>x<小寫 x><高>`，而且**路徑與 `=` 之間至少要有一個空白**。任何一點不符，整個 `![...](...)` 就不是合法的圖片語法，會**原封不動以原始 markdown 文字顯示**（看得到 `![說明](images/a.png =600X200)` 這一整串），圖片不會出現。這是刻意的：打錯字要讓你一眼看見，而不是變成一個和「圖還沒同步完」長得一模一樣的方括號占位。

| 寫法 | 結果 |
|---|---|
| `![a](images/x.png =600x200)` | 正常，600×200 |
| `![a](images/x.png=600x200)` | **打錯（漏空白）**，顯示原始 markdown |
| `![a](images/x.png =600X200)` | 打錯（大寫 X），顯示原始 markdown |
| `![a](images/x.png = 600x200)` | 打錯（`=` 後多了空白），顯示原始 markdown |
| `![a](images/x.png =-5x200)` / `=0x200` | 打錯（尺寸必須是正整數），顯示原始 markdown |
| `![a](images/x.png =x)` | 兩邊都沒給數字，不算尺寸語法，顯示原始 markdown |

漏打空白（`x.png=600x200`）是最常見的一種，所以特別處理：路徑尾端只要長得像 `=<數字>x<數字>`（`=600x`、`=x200` 也算），就一律當成寫錯的尺寸而不是檔名的一部分。判斷只看**最後一個** `=` 之後的那一段，而且那一段必須整段就是尺寸形狀，所以 `images/a=1x2.png`、`images/v1=2.png` 這類真的含 `=` 的檔名不會被誤判。真的想用 `images/a=600x200`（沒有副檔名、結尾又剛好是尺寸形狀）這種檔名，請把檔案改名。

**反斜線逸出對尺寸尾段無效**：`![a](x.png \=600x200)` 仍然會被解析成 600×200（反斜線在區塊解析階段就先被還原了，尺寸拆解看到的已經是 `=`）。要讓 `=600x200` 成為路徑的一部分，只能靠上面那條「檔名不得以尺寸形狀結尾」的限制，也就是改檔名。

### 刻意不實作的

| 項目 | 實際行為 | 原因 |
|---|---|---|
| Setext 標題（`===` / `---` 底線） | `---` 一律是分隔線 | CommonMark 規定 setext 優先，但「段落後面接一條分隔線」是公告最常見的版型，改了會讓既有公告的分隔線突然變成標題。 |
| 縮排式程式碼區塊（4 個空白） | 不當程式碼 | 會和巢狀清單縮排、以及隨手縮排的內容衝突，靜默吞掉正常文字；而且如上表，縮排本來就顯示不出來。請一律用圍欄 ` ``` `。 |
| 清單項內的段落／程式碼區塊 | 只支援單行內容＋縮排續行 | 完整的容器區塊堆疊成本最大，公告場景幾乎用不到。 |
| 清單項內的分隔線（`- * * *`） | 顯示成純文字 `- * * *` | 同上：清單項內只解析行內語法，不做區塊解析。標準 Markdown 會畫成「一個內含分隔線的清單項」。注意 `- ---` 不在此列——它整行都是同一個字元，CommonMark 本身就判定成分隔線，本 MOD 行為一致。 |
| 巢狀清單、巢狀引言超過 4 層 | 一律壓在第 4 層 | 面板內容區只有約 950px 寬，再縮排下去內容會被吃光。 |
| HTML | 一律轉義成可見文字 | 引擎不是瀏覽器；放行任意標記等同開放注入。唯一例外是上面那份原生標記白名單。 |
| 參考式連結 `[文字][id]`、腳註 | 不解析 | 公告是單檔短文，用不到；請直接寫 `[文字](網址)`。 |
| 非 `http` / `https` 的自動連結 | 轉義成可見文字 | 與連結安全政策一致（見「連結行為」一節）。 |
| 裸網址（沒有 `<>` 也沒有 `[]()`） | 不會變成連結 | 避免公告裡任何看起來像網址的字串都變成可點擊區域。請用 `<https://...>` 或 `[文字](https://...)`。 |

### 行為變更提醒（從舊版升級的服主請看）

**段落內的單一換行現在會併回同一段**，跟標準 Markdown 一樣。也就是說：

```markdown
第一行
第二行
```

以前會顯示成兩行，現在會顯示成「第一行 第二行」並自動重排。這是為了讓公告的版面符合 Markdown（引擎本來就會自動重排，硬斷行只會讓畫面變成參差不齊的短行）。

要保留原本的斷行有三種寫法，任選一種：

- 在要斷行的那一行**行尾打兩個空白**
- 在要斷行的那一行**行尾放一個 `\`**
- 兩行之間**空一行**（變成兩個段落，間距會比較大）

另外，中文段落合併時中間會多一個空白（`第一行 第二行`）——這是引擎以空白重組 token 的固有行為，和標準 Markdown 在瀏覽器裡的表現一致。

## 圖片（伺服器同步，推薦）

把 PNG 放進公告根目錄底下的 `images/`，MOD 會自動同步到每位玩家的本機快取，公告中用 `images/<檔名>` 引用。**不需要製作或發布任何圖包 MOD。**

```text
Zomboid/Lua/NoticeBoard/
├── images/
│   ├── safezone.png
│   └── event_banner.png
├── CH/
│   └── 10_welcome.md
└── EN/
    └── 10_welcome.md
```

公告內寫法（`images/` 是固定前綴，不要再寫語系目錄或絕對路徑）：

```markdown
![安全區地圖](images/safezone.png)
```

`images/` 是全語系共用的：所有語系的公告都引用同一批圖，不需要在每個語系目錄下各放一份。

### `images/` 裡的 `00_README.txt`

伺服器啟動時會在 `images/` 放一份 `00_README.txt`，內含 **EN／繁體中文／简体中文／日本語** 四語的檔名規則、容量上限、公告內引用寫法與更新機制摘要，打開資料夾就看得到規則，不必翻本文件。

- 只有在**該檔案不存在**時才會建立，**絕不覆蓋**——可以自由編輯、加自己的筆記，或直接刪掉（刪掉後下次啟動會再放一份）。
- 圖片掃描器只認 `.png`，`.txt` 會被靜默略過：這個檔不會被當成圖片，也不會在 log 產生任何訊息。
- 目錄不存在時會自動建立，所以第一次啟動就會看到 `images/00_README.txt`。

### 檔名與格式限制

- **只支援 PNG**（副檔名 `.png`，不分大小寫）。JPG、GIF、WebP 一律忽略。
- 檔名限 ASCII：英數開頭，其餘只能是英數、底線 `_`、連字號 `-`，長度含副檔名 ≤ 64 字元，且檔名主體不得含 `.`。例如 `safezone.png`、`event-01.png` 可以，`公告圖.png`、`my image.png`、`v1.2.png` 不行。
- 不符合上述規則的 `.png` 會被跳過，並在伺服器 log 記錄 `img-invalid-name`。
- 檔名的**大小寫不列入區分**：`Logo.png` 與 `logo.png` 視為同一張圖（Linux 專用機的檔案系統允許兩者並存）。撞名時只保留排序在前的那一個，被剔除的會 log 記 `img-dupname`。

### 容量上限（全部是預設值，三個都可調）

三個上限都是 Sandbox 選項，**什麼都不設就是下表的預設值**，行為與舊版完全相同。

| 限制 | 預設值 | Sandbox 選項 | 可調範圍 | 超限行為 |
|---|---|---|---|---|
| 單張圖片 | 512 KB（524,288 bytes） | 單張圖片上限（KB）`MaxImageKB` | 64–4096 KB | 跳過該張，log 記 `img-oversize` |
| 圖片張數 | 20 張 | 圖片張數上限 `MaxImageCount` | 1–200 張 | 依檔名排序保留前面的，其餘 log 記 `img-count` |
| 圖片總量 | 4 MB（4,194,304 bytes） | 圖片總量上限（KB）`MaxImageTotalKB` | 4096–16384 KB | 依檔名排序累加，超過的跳過並 log 記 `img-total` |

log 的 `img-oversize` / `img-total` / `img-count` 會一併寫出**當下生效的上限**（例如 `img-count=x.png(max20)`），看到就知道那是你自己設的值、可以去沙盒選項調，而不是 MOD 寫死的牆。

**調高任何一項之前請先想清楚代價**：這三個值決定的是**每一位玩家**要下載多少。圖片越大／越多，每位玩家首次進場的背景同步時間就等比增加（伺服器編碼與客戶端寫檔都是刻意分批進行的），而服主自己在本機測試時完全感覺不到這個成本。客戶端寫檔速度約 90 KB/s，因此總量設到上限 16384 KB 時，玩家首次進場大約要花 **3 分鐘**在背景把圖同步完（同步期間公告文字照常顯示，圖片位置先顯示替代文字）。圖片以內容雜湊快取，同一張圖只會下載一次，之後進場不再重傳。

單張上限最高 4096 KB，剛好等於總量上限的**最低**可設值，因此在任何設定組合下單張都不可能超過總量。

**玩家端有自己的保護上限，服主調得再高也不會突破**：客戶端對「單張大小」「張數」都有寫死的天花板（分別等於上表可調範圍的上界），對端宣告超出範圍的值時客戶端一律改用天花板；另外還有「快取目錄總量上限」與「每個時間窗最多寫入的位元組數」（見下一節），這兩項完全不受伺服器設定影響。也就是說，把上限開到最大是伺服器自己承擔頻寬與等待成本，不會變成灌爆玩家硬碟的手段。

多數情況更好的作法是把圖片本身最佳化：公告面板內容區約 950px 寬，超過這個寬度的像素在顯示時本來就會被等比縮掉，純屬浪費。實測一張 1024×1024 的全彩 PNG 從 1.63 MB 縮成 768×768＋256 色調色盤後只剩 316 KB（省 81%），在面板上肉眼幾乎無差別。

超限的判斷順序是「依檔名字典序」，所以想要保證某張圖一定進得去，就給它排序靠前的檔名。

### 同步是漸進的，大圖要等

同步走的是與公告文字相同的網路通道，且**全程分批處理**，不會讓伺服器或客戶端卡幀。代價是需要時間：

1. 伺服器每 tick 只讀取／編碼約 8 KB，一張 200 KB 的圖大約要 25 秒才編碼完成（空服時也照常進行）。
2. 客戶端拿到分塊後每 tick 只解碼／寫檔約 1.5 KB（客戶端寫檔預算刻意比伺服器小：PZ 的檔案輸出串流沒有緩衝，每個位元組都會實際打到作業系統，用伺服器那個大小會直接掉幀）。一張 200 KB 的圖寫檔約需 140 個 tick。
3. 因此**剛放好圖、玩家剛進場時看到 `[替代文字]` 是正常的**。圖片寫入完成後面板會自動重畫，不必切換公告或重進遊戲。
   - **傳輸中斷會從斷點接下去，不會整張重來。** 分塊收到一半就沒動靜（60 秒內沒有任何新分塊）時，客戶端**保留已收到的分塊**，下一次請求只要「第一個缺的分塊」之後的部分，伺服器就從那裡往後送。客戶端 log 會出現 `image transfer stalled hash=... received=12/40 attempt=1`（`received` 就是保留下來的進度），恢復時是 `imgreq sent images=1 resumed=1`。同一段期間服主新增或覆蓋**別的**圖也不會把正在傳的圖打回起點。
   - 續傳拼回來的內容**照樣要通過完整的內容雜湊驗證**才會標記可用，正確性不因續傳而降低；驗證不過就清掉半成品重來（最多 3 次）。
   - **續傳只在同一次遊戲程序內有效：玩家離開遊戲後，沒下載完的那張圖下次進場會重新下載。** 這是引擎的硬限制，不是偷懶——`getFileOutput` 走 `new FileOutputStream(檔案)`（`LuaManager.java:5818-5840`，沒有 append 多載），一開檔就把檔案截成 0，寫到一半的 PNG 在檔案層面接不下去。唯一能跨場次保存的是 base64 文字（`getFileWriter` 才有 append），但那要**多寫 1.33 倍的位元組到玩家硬碟**去省一段重新下載，而磁碟寫入正是玩家端最稀缺的資源（約 90 KB/s，比伺服器推分塊慢一個數量級以上），下載不是。淨值為負，所以刻意不做。
4. 圖片以內容雜湊命名快取在玩家本機 `Zomboid/Lua/NoticeBoard/cache/<伺服器位址>_<hash>.png`，**只會下載一次**。玩家下次進場不會重傳；只有圖片內容改變（雜湊改變）時才會重新同步。每張圖旁邊會有一個 8 bytes 的同名 `.ok` 完成標記，代表這個檔案曾經通過完整驗證；標記不見或不完整時該圖會重新下載（快取命中只比對大小是不夠的）。
   - 檔名帶伺服器位址（連線時玩家輸入的位址與埠，正規化成 `a-z0-9_`）是**安全隔離**：內容雜湊只有 32 位元，惡意伺服器有辦法做出一張「長度與雜湊都與你這台伺服器某張圖相同」的圖，若快取跨伺服器共用，玩家連過那台之後再連你這台就會看到攻擊者的圖。代價是同一張圖在不同伺服器上各存一份（以圖片體積來說划算）。
   - 舊版（沒有位址前綴）留下的快取檔在升級後**不會被採用**，並會在背景被清空回收空間——來源伺服器已不可考，這是安全修正的必要代價。受影響的圖會重新下載一次。
5. 快取目錄總量上限 **128 MB**，超過就以 LRU（最久沒用到的先走）在背景分批淘汰。淘汰只會動到**目前公告清單沒有用到**的圖，而且每 tick 最多兩張，不會卡幀。PZ 沒有刪檔 API，被淘汰的檔案是被清成 0 bytes（檔名還在、不佔空間）。使用時間記在 `cache/index.txt`；這個檔壞掉或不見只會讓淘汰順序退化成任意，**不影響任何一張快取的有效性**，也不會擋住面板。
   - 128 MB 的取法：單台伺服器的合法總量上界是 16 MB，128 MB 可同時完整快取 8 台「設定拉滿」的伺服器（跑預設 4096 KB 的話是 32 台）。被淘汰的圖再次需要時要重新下載（一台 16 MB 約 3 分鐘），所以上限刻意取得寬鬆。
6. 每 **30 分鐘**的時間窗內，最多寫入 **64 MB** 到快取目錄。撞到之後這個窗內剩下的圖顯示替代文字，client log 出現 `image cache write budget exhausted for this window`；**下一個窗會自動恢復並重新排隊**，不需要重進遊戲。這是防止惡意伺服器不斷輪替圖片清單持續消耗玩家的磁碟寫入，**是玩家端的固定保護值，不隨伺服器設定縮放**。
   - **靜態圖片集不會碰到**：即使服主把總量開到上限 16384 KB、而且每張圖都重試到上限 3 次，累計也只有 48 MB，一個窗內就放得下。
   - **會輪替圖片的伺服器**：這個額度算的是「這位玩家在這個窗內下載過幾個**不同的內容雜湊**」，換 manifest 不會歸零。所以自動產生狀態圖／地圖圖的伺服器有一組實質速率上限：每 30 分鐘 64 MB ÷ 512 KB ≈ **128 張**。撞到只影響當下那個窗，不再像舊版那樣整場遊戲都退回替代文字。
   - **玩家會看到一則遊戲內提示**（公告面板的 toast：「為保護你的硬碟，公告圖片同步已暫停，約 30 分鐘後自動恢復」），**一個時間窗最多一則**，不會洗版。圖片端只有這一種狀態會打擾玩家；淘汰、舊格式回收、重試都只寫 log——那些是背景行為，玩家看到的只會是「圖出現了」。
   - **伺服器端不會收到任何通知，這是刻意的。** 這個額度是玩家端的保護值，回報給伺服器等於多開一條 client→server 的訊息（多一個可被灌爆的接收面），而真正會逼到這個額度的惡意伺服器根本不在乎這則回報。誠實但更新太頻繁的服主可以自己算：**每 30 分鐘 64 MB ÷ 平均圖片大小 ＝ 一個窗容得下的新雜湊數**（512 KB 的圖約 128 個）；伺服器 log 每產生一個新雜湊就有一行 `image encoded`，數那個就知道有沒有逼近。
   - 即便如此，**仍請不要讓每個輪詢週期都產生新的圖片內容**：每個新雜湊都是一次全量重傳＋重新寫檔，玩家端會持續看到同步中的替代文字。需要頻繁更新的資訊建議用文字，或把更新頻率壓到每天數次。

### 換圖：新檔名與原地覆蓋都會自動生效

- **新增或刪除** `images/` 內的檔案 → 下一輪輪詢自動生效。
- **原地覆蓋同名檔案** → 也會自動生效。伺服器每輪輪詢會對已同步過的檔名開檔問一次**檔案大小**（不讀內容、每個檔名每輪最多一次），與上次編碼時的大小不同就自動重新同步，**不必按任何按鈕**。
- **張數越多、原地覆蓋越慢生效**：問檔案大小雖然不讀內容，一次仍要開關一個檔，張數拉高後全部一起問會讓伺服器該影格明顯變慢。因此每輪最多只問 **20 個檔名**，下一輪從上次停的位置接著問，循環輪替（不會有檔案被永久跳過）。最壞的生效延遲＝`圖片張數 ÷ 20`（無條件進位）輪：
  - `MaxImageCount` 用預設的 **20 張**：每輪都問得完，**1 輪**生效——與過去完全相同。
  - 調到 **60 張**：最多 **3 輪**（預設 60 秒輪詢＝3 分鐘）。
  - 調到上限 **200 張**：最多 **10 輪**（預設 60 秒輪詢＝10 分鐘）。
  - **急著讓覆蓋生效就在面板按「重新載入」**（管理員限定）：那條路徑無條件重讀全部圖片，不受每輪 20 個的限制，也不管張數設多少。
- **唯一的死角：新舊圖的位元組數剛好完全相同時偵測不到。** PZ 的目錄列舉 API 只回檔名、沒有檔案時間戳可比對，只能拿檔案大小當變更訊號——這是啟發式，不是保證。碰到這種情況請在面板按「**重新載入**」（管理員限定）或重啟伺服器。想完全避開就改用新檔名（例如 `event-02.png`）並同步改公告內文。
- **覆蓋後的新檔超過容量上限時，那張圖會從公告上消失**，退回 `[替代文字]` 占位：舊的已判定為過期、新的又不合規。log 會記 `img-oversize` 或 `img-total`，把檔案壓到上限內即可自動恢復。
- 覆蓋的當下若剛好讀不到檔案（防毒鎖檔、檔案正在寫入等暫時性 IO 錯誤），伺服器**保留舊圖**、只在 log 記一則 `img-read`，不會讓玩家看到圖片突然消失；**下一次輪到它時**自動再試（張數多的時候不是下一輪，最壞要等一整圈＝上面那個「張數 ÷ 20」）。在它恢復可讀之前，這則 `img-read` 每輪都會留著（只寫一次 log，不會洗版），所以看到 `image issues cleared` 就代表**真的**排除了，不是還沒輪到它。
- **只要有任何一張圖正在編碼，該輪就整輪跳過大小比對**（PZ 的開檔 API 用共用的串流欄位，同時開第二個檔有機會誤傷編碼中的工作）。已排隊等待編碼的圖片同理。編碼完成後的下一輪就會恢復偵測，只是覆蓋後生效時間會多等一個輪詢週期。

### 顯示與排錯

- 圖片寬度超過面板內容寬度時會等比縮小到剛好塞滿，高度也會被夾在面板內容高度的 3 倍之內；調整視窗大小或收合／展開側欄時，當前公告會立即依新的內容寬度重算。**伺服器同步圖（`images/...`）與圖包 MOD 貼圖（`media/textures/...`）走同一套夾限**，兩邊都不必自己先把圖縮好。原圖本來就塞得下時完全不做任何縮放。
- 想自己指定顯示尺寸就用 `![替代文字](images/rules.png =600x200)`（見「支援的 Markdown 語法」的圖片尺寸一列）。指定值一樣會被夾在面板可用寬度與內容高度的 3 倍之內，**縮小顯示尺寸不會減少傳輸量**，圖片檔本身該壓縮還是要壓縮。
- 圖片**靠左對齊**，與標準 Markdown 的 `![]()` 行為一致（不置中）。
- **圖片可以放進 `#` 標題那一行，該行會整行靠左顯示。** 適用 `![說明](路徑)` 與手寫的 `<IMAGE:路徑>` 兩種寫法。字級與顏色與一般 `#` 標題完全相同，只有對齊方式不同，圖片與標題文字的相對位置正常。原因是遊戲的置中只用**文字**寬度去算位置、完全不計圖片寬度，而圖片是用另一套未經位移的座標畫的——兩者硬湊在一起，圖片會與標題文字錯開、甚至直接壓在標題文字上。改成靠左之後圖文共用同一套座標，問題消失。不含圖片的 `#` 標題維持置中；`##`～`######` 與一般內文本來就靠左，全部不受影響。若你就是要置中的大標題，把圖片移到標題的**下一行**即可。
  - **例外：手寫的 `<IMAGECENTRE:路徑>` 不在此列**，該行維持置中。引擎把 `<IMAGECENTRE:>` 強制畫在面板水平正中、與對齊設定無關，改成靠左只會讓標題文字往左跑而圖片留在正中，反而更糟。要把圖片放進 `#` 標題行請用 `![說明](路徑)` 或 `<IMAGE:路徑>`。
  - **靠左是看「這行有沒有寫圖片標記」，不是看「圖片有沒有真的畫出來」。** 所以路徑打錯、圖片還在同步中、檔案超過容量上限、或圖片標記被包在行內程式碼／連結裡（`` `![說明](路徑)` ``、`[![說明](路徑)](網址)`）時，那一行**仍然是靠左的**，但你只會看到 `[說明]` 占位或原始 markdown。排錯時「標題突然不置中」＋「圖片沒出現」是**同一個原因**（圖片沒生效），不是兩個問題——先修路徑，對齊會跟著回來。
- **手寫的 `<CENTRE>`（以及 `<H1>`）那一行仍然不要放圖片**：那是你自己下的排版指令，MOD 不會介入，圖文錯位照樣會發生。
- 引擎原本會把 `<IMAGE:>` 垂直置中對齊「一行文字」，圖片比一行文字高時算出負的位移、直接畫到前面的文字上面。**MOD 會修正這個位移**，`![說明](檔名)` 與手寫的 `<IMAGE:路徑>` 都適用。手寫 `<IMAGECENTRE:>` 不在修正範圍內，而且會強制水平置中。
- 手寫原生 `<IMAGE:路徑>` / `<IMAGE:路徑,寬,高>` / `<IMAGECENTRE:...>` 的**尺寸現在也會被夾限**，與 `![說明](路徑 =寬x高)` 走同一套規則（面板可用寬度、內容高度的 3 倍）。以前這條路徑是原樣交給引擎的，寫 `<IMAGE:a.png,100000,100000>` 會直接畫出面板外，不寫尺寸則是按貼圖原始像素畫。
- **路徑或檔名含排版指令字樣的圖片照常顯示，不必改檔名。** 遊戲的文字面板是用「裸子字串」判斷排版指令的，所以 `media/textures/RED_BANNER.png` 這種路徑會連帶被當成「把顏色改成紅色」的指令，圖後面的整段文字跟著變色。MOD 會自動在這種圖片前後補上一組顏色還原標記，顏色不受影響（包含圖片出現在 `#` 或 `##` 標題行內時，標題後半段仍是標題色；`#` 標題行的**對齊**行為見上面那一條，與顏色無關）。知道有這回事只是為了排查方便：**顏色類**的 `RED`、`ORANGE`、`GREEN`、`GHC`、`BHC`、`RGB:`（全大寫才算）會觸發，而且都救得回來。
- **但「還原標記」只救得了顏色。** 路徑裡若出現 `PUSHRGB:`、`POPRGB`、`SIZE:`、`IMAGE:`、`IMAGECENTRE:`、`VIDEOCENTRE:`、`INDENT:`、`JOYPAD:`、`SETX:`、`SPACE`，引擎會去動顏色堆疊、換字型、解析不存在的參數或推移位置，還原標記幫不上忙，最糟會讓整份公告無法顯示。（`PUSHRGB:` / `POPRGB` 看起來是顏色類，但它們動的是顏色**堆疊**——還原標記本身就是一組堆疊操作，會被路徑裡的那個字樣先抵銷掉，所以救不回來：該張圖之後、同一段粗體／連結範圍內的文字會掉色。）這幾個除了 `SPACE` 與 `POPRGB` 以外全都**帶冒號**，檔名裡本來就不該有冒號；真的遇到請改檔名或改目錄名。
- 手寫原生圖片標記的**逗號參數只能是 0 個或 2 個**：`<IMAGE:路徑>` 或 `<IMAGE:路徑,寬,高>`，寬高都必須是正整數。只寫一個（`<IMAGE:a.png,600>`）會讓引擎在拆參數時對不存在的高度動手而拋錯，**整份公告會變成「無法顯示這則公告」**。因此這種寫法會被換成圖片占位，讓你看得出是哪一張圖壞掉，公告其餘部分照常顯示。想指定尺寸建議一律用 `![說明](路徑 =寬x高)`。
- 同理，**圖片檔名本身不能含半形逗號**（例如 `map,v2.png`）：引擎只要在標記裡看到逗號就會把它當成尺寸參數去拆。這種圖一律顯示成 `[替代文字]` 占位，公告其餘部分照常顯示；把檔名裡的逗號改掉即可。
- 看到方括號占位（例如 `[安全區地圖]`）代表這張圖現在不可用，可能是：還在同步中、檔名不符規則、超過容量上限、公告裡的路徑打錯、或 PNG 檔本身損毀。
- 伺服器端 log 每張圖會有一行 `image encoded name=... bytes=... hash=... chunks=... encodeMs=... spanMs=... maxBatchMs=...`。
- 客戶端 log 對應一行 `image cached hash=... bytes=... chunks=... writeMs=... spanMs=... maxBatchMs=... method=...`；驗證失敗則是 `image verify failed`（會清掉半成品檔並重試，最多 3 次）。
- **怎麼讀這三個時間**：`encodeMs` / `writeMs` 是每一批耗時的**累加**，也就是這張圖真正花掉的 CPU 時間，調整批次大小要看它；`spanMs` 是從開始到完成的牆鐘時間，包含每個 tick 之間的閒置與等待分塊，會隨 tick rate 與 FPS 浮動，**不能**拿來判斷效能；`maxBatchMs` 是單一 tick 的最大耗時，是判斷「有沒有掉幀」最直接的數字。
- client log 出現 `cache discard failed path=...` 代表快取目錄裡有檔案清不掉——PZ 沒有刪檔 API，唯一的手段是把檔案開起來截成 0 bytes，而檔案被別的程式鎖住時這一步會失敗。常見原因：`%USERPROFILE%\Zomboid` 落在 OneDrive 之類的同步資料夾內、防毒即時掃描、或玩家自己拿看圖程式開著那個 PNG。後果只是那幾個檔案這一場遊戲收不回空間（快取總量可能暫時超出 128 MB），公告與圖片顯示都不受影響；把 Zomboid 目錄排除在同步／掃描之外即可。
- 少數情況下 client log 會出現 `image cache disabled: cache path contains RichText-unsafe text ...`。這表示玩家的 Zomboid 目錄路徑含有會讓 PZ 文字面板去拆參數的字樣。完整清單與 log 訊息裡印出來的字樣一致：半形逗號、`<`、`>`、`PUSHRGB:`、`POPRGB`、`SIZE:`、`IMAGE:`、`IMAGECENTRE:`、`VIDEOCENTRE:`、`INDENT:`、`JOYPAD:`、`SETX:`、`SPACE`。此時該玩家的同步圖一律顯示替代文字，公告文字不受影響；解法是把 Zomboid 目錄搬到不含這些字樣的路徑。**顏色類字樣不在此列**：Windows 帳號叫 `FRED`、`GREEN`（全大寫）之類的玩家，同步圖照常顯示，顏色由還原標記處理。

## 圖片與圖包 MOD（`media/textures`）

除了上面的伺服器同步，仍可沿用「另做一個圖包 MOD」的舊做法，適合圖很多、很大、或想跟其他伺服器共用的情況。

公告圖片不支援 HTTP/HTTPS 遠端載入。`![替代文字](路徑)` 中的路徑必須指向本公告 MOD 或其他已安裝、已啟用 MOD 內可由 `getTexture()` 讀取的貼圖（`LuaManager.java:8427-8433`；`ZomboidFileSystem.java:63-69,1446-1459`），建議統一放在：

```text
media/textures/<唯一圖包名稱>/
```

例如圖檔位於 `media/textures/MyServerNoticeImages/safezone.png`，公告中寫：

```markdown
![安全區地圖](media/textures/MyServerNoticeImages/safezone.png)
```

請使用獨特的子目錄名稱，避免與其他 MOD 的貼圖路徑碰撞。路徑錯誤、圖片未安裝或貼圖無法載入時，面板不會崩潰，而會顯示 Markdown 的替代文字；替代文字留空時則顯示通用圖片占位文字。

圖包 MOD 的貼圖與伺服器同步圖**適用完全相同的顯示規則**：尺寸夾限、`=寬x高` 語法、路徑含指令字樣時的顏色還原都一樣（見上一節「顯示與排錯」）。子目錄名稱請避開全大寫的 `RED` / `GREEN` 等字樣以免混淆，但**即使用了也不需要改檔名**，圖照樣正常顯示；要避開的是帶冒號的 `SIZE:` / `INDENT:` / `SETX:` 那一類，以及不帶冒號的 `POPRGB` 與 `SPACE`（完整清單見上一節「但『還原標記』只救得了顏色」那一條）。

### 圖包模板

可建立一個只含圖片的 B42 MOD，讓伺服器透過 Workshop 分發：

```text
MyServerNoticeImages/
└── Contents/
    └── mods/
        └── MyServerNoticeImages/
            └── 42/
                ├── mod.info
                └── media/
                    └── textures/
                        └── MyServerNoticeImages/
                            ├── safezone.png
                            └── event.png
```

最小 `42/mod.info`：

```ini
name=My Server Notice Images
id=MyServerNoticeImages
versionMin=42.20.2
```

把圖包 MOD 的 `id` 加入伺服器 `Mods=`，並把 Workshop 數字 ID 加入 `WorkshopItems=`，確保連線玩家會下載並載入相同貼圖。新增或更換圖檔需要更新圖包 MOD；只修改 `NoticeBoard/` 內的公告文字則不需要重新發布任何 Workshop 項目。

## 連結行為

- 連結必須是 `http://` 或 `https://` 開頭、長度 2048 字元以內的網址才會被接受。點擊後把完整 URL 複製到剪貼簿，並顯示「已複製」＋**網域名稱**（顯示網域是為了讓玩家看得出連結真正指向哪裡——`[顯示文字](網址)` 的顯示文字可以造假）。
- 不符合上述格式的連結（例如 `mailto:`、`discord://`、含空白的網址）會顯示「連結已封鎖」且不寫入剪貼簿。這是刻意的安全限制。
- 下列四個官方根網址及其子路徑會另外嘗試透過遊戲的 `openUrl` 開啟：
  - `https://steamcommunity.com`
  - `https://projectzomboid.com`
  - `https://theindiestone.com`
  - `https://pzwiki.net`
- 其他網址只會複製，不會自動開啟瀏覽器或 Steam overlay。這是引擎的網域白名單限制（`LuaManager.java:1283-1295,7387-7405`），不是連結格式錯誤。
- 裸網址不會自動變成連結，必須使用 `[顯示文字](URL)` 或 `<https://...>` 格式。後者的顯示文字就是網址本身，且只接受 `http` / `https`（其他 scheme 會原樣顯示成文字）。

## Sandbox 選項

| 選項 | 預設值 | 範圍／值 | 說明 |
|---|---|---|---|
| `PopupMode` | `2`（僅有未讀公告時） | `1` 每次進入皆彈出；`2` 僅有未讀公告時；`3` 永不自動彈出 | 只控制進場時是否自動開啟主面板。玩家仍可用浮動按鈕手動開啟；在線更新仍會顯示通知與未讀紅點。 |
| `PollIntervalSeconds` | `60` | 最小 `10`、最大 `3600` | 權威端重新掃描公告檔案的實際秒數。管理員也可在面板按「重新載入」要求伺服器立即重讀。 |
| `DefaultLanguage` | `EN` | **下拉選單**，29 個 PZ Translate 語系代碼 | 這個語系的目錄是**全體共用底稿**：裡面沒有 `.only` 標記的檔案會出現在所有語系玩家面板上，玩家自己的語系再以同名檔覆蓋（詳見「玩家會看到哪些公告」）。代碼同時就是 `NoticeBoard/` 底下的目錄名。改成下拉是因為手打字串打錯（小寫 `jp`、寫成 `zh_TW`）只會靜默退回 `EN`，服主通常不會發現。**這份清單是「MOD 接受的代碼」而不是「你實際建立了哪些目錄」**——沙盒選項在載入期就被解析完（`CustomSandboxOptions.java:80-105`），沒有執行期產生選項的機制，而且沙盒是建立世界時設定的，那時公告目錄往往還不存在（首次啟動才 bootstrap）。要看實際有哪些語系目錄，看 server log 的 `notice languages=` 那行（清單變化時才寫一次），或在遊戲內開面板的「語言」選單——那份才是偵測式的。舊版存成字串的 ini 值仍然吃得下（`validateDefaultLanguage` 同時接受代碼字串與索引）。 |
| `NotifySound` | 開啟 | 開／關 | 有新公告或公告更新時，除了畫面上的 toast 再播一聲短提示音（MOD 自帶的短提示音；**不受玩家的「音效音量」選項影響**——MOD 自帶音效走非 bank 通道，那條選項只作用於遊戲本體的 FMOD 音效。玩家可在「選項 → MODS」自行關閉或調音量，你這個沙盒選項是整台伺服器的總開關）。**一批只響一次**，不會每則公告都響；玩家換公告語系時不響（那不是新內容）。玩家全部已讀、沒有 toast 可跳時也不會響。 |
| `MaxImageKB` | `512` | 最小 `64`、最大 `4096` | 單張同步圖片的大小上限（KB）。詳見「圖片（伺服器同步，推薦）」的容量上限一節。 |
| `MaxImageCount` | `20` | 最小 `1`、最大 `200` | 同步圖片的張數上限。 |
| `MaxImageTotalKB` | `4096` | 最小 `4096`、最大 `16384` | 所有同步圖片的總容量上限（KB）。 |

上面三個圖片上限**調高＝每一位玩家的同步量等比增加**，代價由玩家的等待時間承擔；玩家端另有不受伺服器設定影響的保護上限，詳見容量上限一節。

`DefaultLanguage` 可使用目前 B42 白名單內的代碼：`AR`、`CA`、`CH`、`CN`、`CS`、`DA`、`DE`、`EN`、`ES`、`ES_CL`、`ES_MX`、`FI`、`FR`、`HU`、`ID`、`IT`、`JP`、`KO`、`NL`、`NO`、`PL`、`PT`、`PTBR`、`RO`、`RU`、`STREW`、`TH`、`TR`、`UA`。

## 檔案大小限制

- 單一公告檔上限為 200 KB（204,800 UTF-8 bytes）。超過上限的檔案不會送進 manifest，也不會顯示給玩家；伺服器 log 會記錄 `oversize`。
- 套用玩家語系與 `DefaultLanguage` fallback 後，單一語系的有效公告總量上限為 512 KB（524,288 UTF-8 bytes）。
- 超過 512 KB 時，先依數字前綴由小到大排序並保留前面的公告，再從排序尾端開始剔除，直到總量回到上限內。換句話說，數字前綴越小，保留優先順序越高。
- 每個語系（含 fallback 合成後）最多 200 個公告檔。超過時同樣依數字前綴由小到大保留、從尾端剔除，並以 `trimmed` 記錄。此上限確保單一同步封包不會超過引擎的網路緩衝上限。
- 被總量上限或檔案數上限剔除的檔案不會出現在該語系的 manifest；伺服器 log 會以 `trimmed=<語系>/<檔名>` 列出。

若公告具有不同優先級，請把較重要的檔案設為較小的數字前綴，並避免單一圖片或長篇內容直接塞入公告文字。

## 首次啟動的 bootstrap 範例

伺服器啟動時，若所有支援語系目錄中都找不到任何 `.md` 或 `.txt` 公告，MOD 會自動建立：

```text
NoticeBoard/EN/10_welcome.txt
NoticeBoard/CH/10_welcome.txt
```

bootstrap 使用 `.txt` 是因為 PZ 的寫檔 API 不允許建立 `.md`（`LuaManager.java:1034,6725-6765`）；讀取端則同時支援 `.txt` 與 `.md`。兩個範例檔會展示 H1、H2、醒目文字、清單、分隔線、連結與圖片語法，可直接修改成正式公告，也可在建立自己的檔案後刪除。

範例引用的是本 MOD 自帶的 `media/ui/NoticeBoard/nb_sample.png`，目的是讓你一開機就看得到「圖片語法確實可用」。要換成自己的圖，**最簡單的方式是把 PNG 丟進 `NoticeBoard/images/`**，用 `![說明](images/my-image.png)` 引用即可（同步圖片檔名只接受 ASCII 英數、`_`、`-`），伺服器會自動同步給每位玩家（見「圖片」一節）；沿用貼圖包 MOD 的路徑引用也仍然支援。

若引用的圖不存在（路徑打錯、檔案還沒同步完、圖包 MOD 沒啟用），面板**不會崩潰**，而是顯示 Markdown 的替代文字（`![替代文字](...)` 的方括號內容），例如 `[公告圖片範例]`。**看到方括號占位就代表貼圖沒載到**，請檢查路徑與圖包 MOD 是否已啟用。

只要任一支援語系已經存在公告檔，bootstrap 就不會補建其他語系。若日後刪除所有公告，下一次啟動權威端時會再次建立 EN 與 CH 範例檔。

## 一鍵重建範例：面板上的「重建範例」按鈕

bootstrap 只在「完全沒有公告」時建立兩個入門檔（上一節）。想要一份**完整**的參考資料——每一種支援的 Markdown 語法、分類宣告、`.only` 語系限定、可直接改用的正式公告範本——按公告面板工具列上的「重建範例」，再從選單挑一個語系。它只給 access level 為 `admin` 的玩家看得到，伺服器端會再驗一次權限。

**這些檔案會直接寫進正式公告目錄、寫完立刻推給玩家**，不會落在任何隱藏的參考資料夾，也不需要你手動複製任何東西。

### 選單只有兩個語系

按下按鈕會開出原生 context menu，只有兩項，各自都把「會覆寫 `categories.txt`」寫在標籤裡：

- 重建繁體中文範例（會覆寫 categories.txt）→ `CH`
- 重建 English 範例（會覆寫 categories.txt）→ `EN`

沒有第三個選項；client 與 server 都只接受精確的 `CH` 或 `EN`，其他值一律拒絕。**選定之後才會送出請求**，只是把選單打開再關掉不會寫任何檔案，也不會吃掉冷卻。

### 它做什麼、不做什麼

選定語系後，權威端固定寫這 5 個檔（`<語系>` = 你選的那一個）：

```text
NoticeBoard/README.txt
NoticeBoard/categories.txt
NoticeBoard/<語系>/10_welcome.txt
NoticeBoard/<語系>/10_news/20_markdown_showcase.txt
NoticeBoard/<語系>/20_rules/30_server_rules.only.txt
```

根層那兩個共用檔每次都寫，語系三檔只寫你選的那一個語系。

- **這是正式公告，符合可見規則的玩家不必等下一輪輪詢。** 5 個檔全部寫成功後，伺服器會立即刷新快照並推送；新增或內容有變的公告再依既有規則觸發通知、提示音與未讀紅點。
- **只覆寫上面這 5 個相對路徑。** 另一個語系目錄、你自己的其他公告、放在公告目錄裡的額外檔案與 `images/` 一個位元組都不會被動到；這個功能沒有任何刪除路徑。
- **根層 `categories.txt` 會被取代。** 產生的版本只宣告 `10_news` 與 `20_rules`（各有 EN 與 CH 標籤）。你原本宣告的其他分類不再被宣告，會連同裡面的公告一起從側欄消失——公告檔仍然在磁碟上，把那一行補回 `categories.txt` 就整個分類回來。**按之前請先備份 `categories.txt`**，或是在還沒設定過分類的公告板上再按。
- **那 5 個檔會被覆寫。** 按鈕的用途就是「把範例還原成出貨版本」，所以改在這 5 個路徑裡面的內容，下次重建同一語系時會消失。要保留修改請另存成不同檔名——但記得檔名就是公告 ID，改名等於變成一則全新公告，看得到的玩家會再收到一次通知。
- **`README.txt` 與 `categories.txt` 不是公告。** 它們在公告根層，而掃描只列舉 `NoticeBoard/<語系>/` 與 `categories.txt` 已宣告的分類目錄，所以玩家看不到這兩個檔，它們也不吃任何容量上限。
- **可見範圍照既有規則走。** `DefaultLanguage` 設成 `EN` 時，產生 EN 會讓每一位玩家都看到 `10_welcome.txt` 與 `20_markdown_showcase.txt`（英文底稿），而 `30_server_rules.only.txt` 因為有 `.only` 標記只有讀 EN 的玩家看得到；改成產生 CH，那三則就只有讀 CH 的玩家看得到。兩個語系都要就再按一次、選另一個：那會補上該語系的三則公告，並用完全相同的內容重寫根層兩個共用檔。

### 寫入順序與部分寫入

5 份資源會先全部讀進記憶體，缺任一份就**一個檔都不寫**。之後逐檔寫入，每寫完一檔就沿用既有的寫後讀回驗證，順序固定是：

1. 選定語系的三個公告檔
2. `NoticeBoard/categories.txt`
3. `NoticeBoard/README.txt`

**這不是原子操作。** 中途失敗時，前面已驗證成功的檔案會留在磁碟上。順序是刻意這樣排的：最可能出現的中間狀態是「新公告已落地、`categories.txt` 還是舊的」，此時那兩則分類公告會在 `categories.txt` 落地前暫時看不到——而不是分類設定先被清掉、卻沒有公告可看。排除原因後再按一次即可，重建完全可重複、不會累積殘留。

### 冷卻與回饋

每位管理員有自己的 **10 秒**冷卻（與「重新載入」的冷卻分開，兩顆按鈕不會互相吃掉額度）。ack 只有 `success`／`failed`／`cooldown`／`forbidden` 四種，伺服器針對每一次請求回傳下列結果：

| 提示 | 意思 |
|---|---|
| 已送出 `CH`／`EN` 範例重建要求。 | client 端已把指令交給網路層；結果會由下面四種之一接著跳出。伺服器收到並通過權限、冷卻與語系檢查後才記 `examples requested username=<玩家> lang=<CH\|EN>`——log 有這一行才代表真的開始寫 |
| 範例已寫入伺服器的 `NoticeBoard/`，共 5 個檔案，公告已更新。 | 5 個檔全部落地並通過寫後讀回驗證，快照也刷新成功（log：`examples written count=5 lang=<CH\|EN>`）。檔數固定是 5，而且只有成功回覆才帶檔數；這則提示不帶語系 |
| 伺服器重建範例失敗，請查看伺服器 log。 | 資源缺檔、磁碟寫入失敗、快照刷新失敗，或語系不是 `CH`／`EN`——**四種原因在玩家端是同一則提示**，只有伺服器 log 分得出來：`example pack asset unavailable path=...`（零寫入）、`example pack write failed path=... written=N`（前 N 個受管檔已落地）、`example pack refresh failed lang=... files-written=5`（5 個檔都已寫進磁碟，但快照沒刷新成功，所以**不敢回報成功**——按「重新載入」或等下一輪輪詢就會推出去）、`examples invalid lang username=<玩家> lang=<值>`（零寫入，10 秒節流且用獨立的節流 key，不與寫入結果互相蓋掉） |
| 剛剛才重建過範例，請稍等一下再試。 | 撞到 10 秒冷卻，這一次完全沒有寫任何檔 |
| 需要管理員權限才能重建範例。 | 伺服器端的權限驗證擋下（例如權限剛被撤掉） |

**回覆本身不保證送達。** 若只看到「已送出」而沒有後續結果，代表玩家已斷線或 server→client 回覆傳送失敗（伺服器 log 的 `examples result send failed`）；此時磁碟上的檔案**可能已經更新**，請直接看檔案與 log，不要假設沒寫。語系不合法時不寫任何檔、也不消耗冷卻額度，只會節流地記 log，不會讓偽造封包灌爆 log。

### emoji 在範例裡刻意缺席

產生出來的檔案一個 emoji 都沒有，`README.txt` 也把原因寫在裡面：**emoji 不會弄壞任何東西，但遊戲畫不出來**（詳見「Emoji 與特殊符號」一節）。PZ 用預先烘焙的點陣字型，沒有作業系統 emoji 字型的 fallback，缺字會變成 `?` 或整個不繪製。公告標題、分類標籤、內文都不要用 emoji 傳達必要資訊——改用文字、`NoticeBoard/images/` 裡的 PNG，或前置 MOD 提供的共用圖示。

## 換掉提示音

提示音是 MOD 自帶的音檔，路徑固定在 `42/media/sound/MinidoracatNBNotify.wav`。引擎找音效的順序是
`event:/<名稱>` → `media/sound/<名稱>.ogg` → `media/sound/<名稱>.wav`（`GameSounds.java:95-137`），
所以 **`.ogg` 會優先於 `.wav`**，而後載入的 MOD 會覆蓋先載入的同路徑檔案（`ZomboidFileSystem`
的 `activeFileMap`，覆蓋時 log 會印 `mod "X" overrides ...`）。換音效有兩條路：

1. **只給自己的伺服器用**：直接換掉 MOD 目錄裡那顆 `.wav`。建議走
   `python scripts/prep_notify_sound.py --src <你的音檔.wav>`，它會自動修剪頭尾靜音、轉單聲道、
   把峰值壓到 0.32 並補淡入淡出，然後跑一次規格檢查。原始素材常常是滿刻度（峰值 1.0）又長達數秒，
   直接複製進去會很吵——**自帶音效不受玩家的音效音量選項影響**，只有本 MOD 自己的音量設定管得到。
2. **不想動 MOD 目錄**：另做一個載入順序排在本 MOD **之後**的小 MOD，放
   `media/sound/MinidoracatNBNotify.ogg`。

兩條路都需要**重啟遊戲**才生效：`GameSounds` 對每個音效名只解析一次並快取。

輸入格式只吃未壓縮的 `.wav`（`prep_notify_sound.py` 用 Python 標準庫，解不了 mp3）與引擎認的
`.ogg`／`.wav`；**mp3 不能直接用**，請先自行轉檔。素材若不是自己做的，公開發布前請自行確認授權
——商業作品（動畫、遊戲）的音效通常不允許再散布。

## 玩家自己的音效設定

面板工具列的「語音」按鈕可直接切換通知聲音，不需要修改音檔：

- **原提示音（預設）**：沿用上節的 `MinidoracatNBNotify.wav`。
- **中文／English／日本語**：播放各自的公告語音；繁體與簡體中文共用中文聲音。
- **自動**：跟隨遊戲語系，非中／英／日語系使用英文；不跟隨面板的公告文字語系。

選擇存在 `Zomboid/Lua/NoticeBoard/settings.ini` 的 `voice` 欄位（全域偏好，不分伺服器），
選擇時立即播放該語音試聽，之後通知沿用同一選擇；不重載公告、不改已讀狀態。寫入失敗時本場仍生效，畫面會提示並在背景重試。
三語資產為 `42/media/sound/MinidoracatNBVoiceCH.wav`、`MinidoracatNBVoiceEN.wav`、
`MinidoracatNBVoiceJP.wav`；重新生成的參數在 `scripts/voice_lines.json`，
處理流程見 `scripts/prep_notify_sound.py` 檔頭。更換這些資產同樣需要重啟遊戲。

「語音」旁的**音量滑桿**顯示 0–100%（步進 5），和下方「選項 → MODS」共用同一音量：
拖曳時只更新本場音量並停止舊試聽，放開滑桿（含游標已移出滑桿）後保存並以新音量試聽；
重複選擇語音會停止上一段再播放；關閉面板或用遊戲快捷鍵隱藏介面，也會停止試聽並結束拖曳。
音量為 0、個人提示音關閉或伺服器停用提示音時不播放，畫面會說明目前靜音；
保存失敗會提示重新操作滑桿再試，不會宣稱已存檔。

玩家在遊戲的**選項 → MODS** 分頁會看到本 MOD 的兩個設定（走 PZ 原生的 `PZAPI.ModOptions`，
值存在 `Zomboid/Lua/ModOptions.ini`）：

| 設定 | 預設 | 說明 |
|---|---|---|
| 新公告播放提示音 | 開 | 玩家自己的開關 |
| 公告提示音音量（0-100） | 60 | 0 = 靜音 |

與沙盒選項 `NotifySound` 是 **AND** 關係：你在沙盒關掉，玩家怎麼設都不會響；你開著，玩家仍可自己關。

## 緊急公告：怎麼讓改動馬上生效

一般情況下權威端每 `PollIntervalSeconds`（預設 60 秒）掃一次公告檔案，改完最慢一輪就會推給所有在線玩家
並跳出通知與提示音。要更快有兩條路，**沒有第三條**：

1. **管理員在遊戲內按面板右上的「重新載入」**——立刻重讀全部公告與圖片並推送，這是真正的即時路徑
   （只有 access level 為 admin 的玩家看得到那顆按鈕，且伺服器端會再驗一次權限）。
2. **把 `PollIntervalSeconds` 調到最小值 `10`**——無人操作也最多延遲 10 秒。代價是權威端每 10 秒
   重讀一次所有公告檔（公告是純文字，成本遠低於圖片；圖片的偵測本來就分批進行）。

**沒有「存檔就立刻生效」的檔案監看機制**，這不是偷懶：引擎的 `DebugFileWatcher` 只註冊 media 根目錄與
messaging 目錄（`DebugFileWatcher.java:40-50`），公告所在的 cachedir 不在其中；而它的通知是分派給 Java 的
`PredicatedFileWatcher` 回呼（`:133` 起），Lua 端沒有任何接口可以掛進去。伺服器 console 指令表也是 Java
寫死的（`GameServer.java:1288` 的 `handleServerCommand`），MOD 無法註冊自己的指令。

## 玩家本機留下哪些檔案

玩家端的狀態不全在同一個地方，排錯時要知道去哪找：

| 檔案 | 內容 | 寫入時機 |
|---|---|---|
| `Zomboid/Lua/NoticeBoard/settings.ini` | 語系偏好與公告側欄收合偏好（全域，不分伺服器） | 玩家改語系或按側欄開關的當下；寫入失敗會提示並由背景維護輪重試 |
| `Zomboid/Lua/NoticeBoard/readstate.ini` | 已讀狀態（依伺服器分開記，比對內容雜湊） | 玩家看過某則公告的當下 |
| `Zomboid/Lua/NoticeBoard/cache/` | 同步下來的圖片與 `index.txt`（LRU 使用時間） | 圖片同步完成時；總量上限 128 MB |
| **`Zomboid/Lua/layout.ini`** | **面板與浮窗的位置、尺寸、pin／visible** | **只有存檔與離開遊戲時**（`Events.OnPostSave`，由 `GameWindow.java:790-805` 與 `IngameState.java:1341-1349` 在 `save(true)` 之後觸發；MP 客戶端走同一條） |

最後一項刻意**不放在** `NoticeBoard/` 下：那是 PZ 原生的視窗版面機制（`ISLayoutManager.lua:6`／`:15`／`:53`），全部原版視窗與 MOD 視窗共用一份，並依解析度分區（`[1920x1080]`、`[1920x1009]` 各一組，全螢幕與視窗化各自記憶）。跟著原生機制走就不必自建存檔格式，代價是兩件事要知道：

- **遊戲當掉或被強制關閉時，這一輪調整過的視窗位置不會留下**（vanilla 所有視窗都一樣，不是本 MOD 的行為）。相對地 `settings.ini` 與 `readstate.ini` 是改動當下就寫，不受影響。
- 要把某位玩家的面板位置／尺寸整個重置，請他按面板上的「重設大小」，或在 `Zomboid/Lua/layout.ini` 裡刪掉 `MinidoracatNBPanel` 與 `MinidoracatNBFloatButton` 這兩行（其餘行屬於別的視窗，不要動）。

## 維運檢查

1. 確認檔案位於正確的 cachedir，而不是 Workshop MOD 目錄。
2. 確認玩家語系與 `DefaultLanguage` 目錄使用正確的大寫 Translate 代碼。
3. 確認跨語系公告使用完全相同的檔名，且同一語系的所有分類內沒有重複檔名。
4. 使用分類時，確認目錄 key 已列在根層 `categories.txt`，再等待 `PollIntervalSeconds`，或由管理員按面板上的「重新載入」。
5. 若內容沒有出現，檢查 server console 與 `Zomboid/Logs/` 中含 `[MinidoracatNoticeBoardFor42]` 的紀錄，特別留意 `category-*`、`dup-id`、`oversize`、`trimmed`、`invalid-id`、讀檔錯誤與非法 `DefaultLanguage` 警告。
6. 若圖片沒有出現，先確認是不是還在同步（等一下再看），再檢查 server log 的 `image issues:`（`img-invalid-name` / `img-dupname` / `img-oversize` / `img-count` / `img-total` / `img-read`）與 client log 的 `image verify failed` / `image transfer timed out`。原地覆蓋同名圖檔會自動生效（見「換圖：新檔名與原地覆蓋都會自動生效」），只有新舊檔位元組數剛好相同時才**必須**按「重新載入」；張數調高時覆蓋最多要等 `張數 ÷ 20`（無條件進位）輪才會被偵測到，不想等一樣按「重新載入」。
